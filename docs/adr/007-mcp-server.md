# ADR-007: MCP server for AI-assisted document authoring

## Context
Documents in WoMD are meant to be co-authored: generated by neural networks and refined
by humans in the editor. Agents need a safe, capability-rich way to create and modify
documents *without* being able to execute programs or escape a designated folder. The
Model Context Protocol (MCP) is the de-facto stdio/JSON-RPC surface for LLM tool use.

Requirements:
- Rich document functionality (create/read/edit/search/organize), Markdown-aware edits
  that keep diffs minimal (Invariant 2).
- Hard confinement to a designated root; OS system directories, the home directory
  itself, Desktop-style profile folders, and credential dirs are denied as roots or
  targets; nested folders of a valid root stay fully usable.
- No program execution, no network.
- A versioned contract so that future agents (and the humans prompting them) can tell
  what changed when the editor evolves — and a written rule that MCP must be updated in
  lockstep with editor capabilities.

## Options
1. **`rmcp` (official Rust SDK).** Rejected for now: pulls an async runtime and a large
   dependency tree for a transport that is ~200 lines of newline-delimited JSON-RPC. The
   server is structured so a future switch only replaces `server.rs`.
2. **Reuse the Tauri command surface.** Rejected: those commands assume a live
   `DocumentBuffer`/UI session; MCP agents operate on files in a root folder.
3. **`editor-mcp` crate: hand-rolled stdio JSON-RPC + sandboxed tool layer over
   `editor-storage`/`editor-markdown`/`editor-git`.** Chosen.

## Decision
New crate `crates/editor-mcp`:

- `sandbox::Workspace` — canonicalized root; denies filesystem/drive roots, the home
  dir and its top-level profile folders as roots, OS system subtrees (Windows/Unix/
  macOS), credential dot-dirs, `.git` internals and `*.womd-tmp-*`; `..`/absolute/
  symlink escapes rejected per request. Temp directories are explicit exceptions so
  tests and headless runs work inside OS temp space.
- `manifest.rs` — single source of truth for the versioned contract: every tool carries
  `since`/`deprecated_in` metadata; `api_manifest` tool and `womd://manifest` resource
  serve the whole contract to clients.
- `tools.rs` — ~19 tools: tree listing, paged read, create/write/append, atomic
  multi-op `edit_document` (replace / line / byte ops, `dry_run`), delete/move/mkdir,
  content + filename search, `markdown_outline` / `markdown_block_edit` /
  `markdown_toggle_task` built on the lossless parser + `streaming_save` (minimal
  diffs), read-only `git_status`/`git_diff`/`git_log` via the `VersionControl` port,
  and `api_manifest`.
- **Every mutating tool call is a separate git commit whose message the agent
  supplies** (`commit_message`; `commit:false` opts out). Implemented as
  `git add -A -- <touched paths>` + `git commit --only` (`GitCli::commit_paths`,
  `:(top,literal)` pathspecs) so unrelated staged work is never swept in; the
  workspace is `git init`'d (`GitCli::init`) on first commit with a seeded local
  identity only when none is configured. API 2.0.0.
- **Write policy (API 3.0.0)**: writes cannot create executables (extension list
  covers Windows installers/scripts and unix binary formats), credential material
  is neither readable nor writable, build/CI/app configuration and editor/agent
  config dirs are read-only, bulk traversal never follows symlinks, component
  names are NTFS-hygienic (device names, ADS, trailing dots), canonicalized paths
  are re-checked (8.3 aliases), read-modify-write tools are compare-and-save, and
  `editor-git` resolves `git` to an absolute PATH entry so a planted binary in
  the workspace can never be executed.
- `server.rs` + `womd-mcp` binary — newline-delimited JSON-RPC 2.0 over stdio;
  `initialize` negotiates protocol `2025-06-18` (compat `2024-11-05`, `2025-03-26`);
  domain errors become `isError` tool results, protocol errors use JSON-RPC codes.

Versioning: `MCP_API_VERSION` semver — MAJOR for removals/incompatible changes, MINOR
for additive tools/optional params, PATCH for internal fixes; deprecated tools survive
one MAJOR. The change-protocol checklist lives in docs/mcp.md and AGENTS.md so future
agents know MCP must evolve with the editor.

Co-editing sync (`editor-ui`): an mtime watcher over open tabs detects MCP writes —
clean buffers reload automatically; dirty buffers keep local edits and surface a
conflict banner naming the commit sha/message (identified via the
`Generated-By: womd-mcp` trailer). Human saves inside a repository create
path-scoped commits of their own (`Generated-By: womd-ui`), so both authors share
one linear history.

## Consequences
- AI workflows get a rich, safe authoring surface; source preservation (Invariant 1)
  and minimal diffs (Invariant 2) carry over to machine edits via `streaming_save`.
- One extra crate, std-only transport (`serde_json`), no async — build stays lean.
- Contract drift risk is mitigated mechanically: `manifest_lists_all_dispatched_tools`
  fails if a spec has no handler; docs prescribe the update checklist.
- Deliberately out of scope: process execution, arbitrary git writes (the only write
  is the per-change `commit_paths` commit; stage/commit/push tools are not exposed),
  network access, MCP transports other than stdio (HTTP/SSE can wrap the same
  `Tools` later).
